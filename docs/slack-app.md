## 1부. Prism 슬랙 앱 만들기 (딱 한 번, 약 10분)

준비물: 슬랙 계정, 앱을 만들 워크스페이스(회사 슬랙 또는 연습용 슬랙).

1. 브라우저에서 <https://api.slack.com/apps> 를 열고 로그인해요. (1분)
2. **Create New App** → **From a manifest** 를 눌러요. (1분)
3. 워크스페이스를 고르고 **Next** 를 눌러요.
4. 위쪽에서 **JSON** 탭을 고르고, 안에 있던 글을 모두 지운 뒤 [`slack-app-manifest.json`](slack-app-manifest.json) 파일 내용을 통째로 붙여 넣어요. (2분)
5. **Next** → 내용을 확인하고 **Create** 를 눌러요.
6. 왼쪽 메뉴 **OAuth & Permissions** 에서 **PKCE** 가 켜져 있는지 확인해요. 꺼져 있으면 켜요. (1분)
   - ⚠️ PKCE는 **한 번 켜면 직접 끌 수 없어요.** (슬랙 고객센터에 요청해야 해요.) 그래서 Prism 전용 새 앱에서만 켜세요.
7. 왼쪽 메뉴 **Basic Information** → **App Credentials** 에서 **Client ID** 를 복사해요. 모양은 `1234567890.1234567890` 이에요. (1분)
   - ⚠️ 그 아래의 **Client Secret** 은 **필요 없어요.** 복사하지도, 누구에게 보내지도 마세요.
8. Client ID를 Prism에 넣어요. 둘 중 하나만 하면 돼요. (1분)
   - **나만 써 볼 때:** Prism → 확장 → 슬랙 → **고급** → Client ID 붙여 넣기 → **Client ID 저장**
   - **모두에게 배포할 때:** `src-tauri/slack-app.json` 의 `"clientId": ""` 따옴표 안에 붙여 넣고 새 버전을 만들어요. (Client ID는 공개돼도 되는 값이에요.)
9. **시험:** [슬랙으로 연결] → [허용] → "연결됨"이 보이고 채널 목록에서 채널을 고를 수 있으면 성공이에요. (2분)

### 다른 회사 슬랙에서도 쓰게 하려면 (나중에)

여기까지만 하면 **앱을 만든 워크스페이스에서만** 연결돼요. 다른 워크스페이스에도 열려면 왼쪽 메뉴 **Manage Distribution** → 체크리스트 완료 → **Activate Public Distribution** 을 눌러요.

켜기 전에 꼭 알아 두세요.

- **속도 제한:** 슬랙 마켓플레이스 승인 없이 밖으로 배포한 앱은 메시지 읽기(`conversations.history`)가 **1분에 1번, 한 번에 15개**로 줄어요. 슬랙 칸이 여러 개면 "슬랙 요청이 많아요"가 자주 보여요. 회사 안에서만 쓰는 앱(internal)은 해당하지 않아요. 널리 배포하려면 마켓플레이스 심사를 받거나, 회사마다 1부를 따라 자기 앱을 만드는 게 좋아요. ([슬랙 공지](https://docs.slack.dev/changelog/2025/05/29/rate-limit-changes-for-non-marketplace-apps))
- **확인 필요:** 슬랙 배포 안내는 돌아올 주소가 https여야 한다고 적고 있어요. `http://localhost` 주소로 배포 체크리스트가 통과되는지는 문서에 없어요. 막히면 개발 담당에게 알려 주세요(3부의 '남은 확인' 참고).

### 막혔을 때

| 보이는 것 | 할 일 |
| --- | --- |
| 매니페스트를 붙였더니 빨간 오류 | 파일 전체를 빠짐없이 복사했는지 확인해요. 그래도 안 되면 오류 문장을 그대로 개발 담당에게 보내요. |
| "슬랙 앱 설정에서 PKCE가 꺼져 있어요" | 6번을 다시 해요. |
| "돌아올 주소(Redirect URL)가 등록되지 않았어요" | **OAuth & Permissions** → **Redirect URLs** 에 주소 3개가 있는지 확인해요. |
| "Client ID가 맞지 않아요" | 7번에서 Client ID를 다시 복사해요. |

## 2부. 연결하기 (쓰는 사람, 약 1분)

1. Prism → **확장** → **슬랙** → **[슬랙으로 연결]**
2. 브라우저에 열린 슬랙 화면에서 워크스페이스를 확인하고 **[허용]**
3. "허락을 받았어요"가 보이면 창을 닫고 Prism으로 돌아와요. 끝이에요.

- Prism은 **내가 볼 수 있는 채널을 읽기만** 해요. 메시지를 보내거나 고치지 못해요.
- **관리자 승인이 필요하다고 나오면:** 슬랙 화면에서 승인 요청을 보내고, Prism에서는 **[그만두기]** 를 눌러요. 승인됐다는 알림을 받은 뒤 [슬랙으로 연결]을 다시 눌러요.
- 브라우저 창을 닫아 버렸으면 **브라우저 다시 열기** 를 눌러요. 5분이 지나면 처음부터 다시 해요.
- 오랫동안(약 30일) 안 쓰면 연결이 만료될 수 있어요. 연결을 끊고 다시 연결하면 돼요.
- [연결 끊기]는 이 컴퓨터에 저장한 값을 지워요. 슬랙 쪽 허락까지 없애려면 슬랙의 앱 관리 화면에서 Prism을 제거해요.

## 3부. 설계 결정과 근거 (개발용)

2026-11-27에 슬랙 공식 문서를 확인했다.

### 결정: PKCE + localhost, client secret 없음, 중계 서버 없음

| 질문 | 답 | 근거 |
| --- | --- | --- |
| 슬랙이 PKCE를 지원하나 | 지원. 켜면 앱이 공개 클라이언트가 되고(되돌릴 수 없음), 토큰 교환에 `client_secret`을 넣지 않는다. `S256`만 지원 | [Using PKCE](https://docs.slack.dev/authentication/using-pkce/) |
| 갱신에도 secret이 필요 없나 | 데스크톱 리다이렉트로 받은 토큰은 필요 없다 | 같은 문서 |
| https 리다이렉트가 필요한가 | 일반 규칙은 https지만, PKCE를 켠 앱의 `localhost`(예시가 `http`)는 데스크톱 리다이렉트로 취급한다. PKCE를 켠 적 없으면 서버 리다이렉트로 취급해 secret을 요구한다 | 같은 문서, [Installing with OAuth](https://docs.slack.dev/authentication/installing-with-oauth/) |
| 어떤 토큰을 받나 | 데스크톱 리다이렉트는 봇 권한을 요청할 수 없다. `user_scope`만 요청한다 | Using PKCE |
| 토큰 만료 | 만료형이면 접근 토큰 12시간, PKCE 앱의 갱신용 값은 30일. 갱신용 값은 한 번만 쓸 수 있다 | Using PKCE, [Token rotation](https://docs.slack.dev/authentication/using-token-rotation/) |

client secret을 앱에 넣는 방법은 버렸다. 배포한 앱 파일에서 누구나 꺼낼 수 있다. 중계 서버는 운영비와 토큰이 지나가는 지점이 생기는데, PKCE면 필요 없다.

`prism://` 같은 커스텀 스킴도 되지만 쓰지 않았다. OS 등록(딥링크 플러그인)이 필요하고 개발 실행에서 시험하기 어렵고, 슬랙이 토큰 만료를 강제한다.

### 동작

- 코드: `src-tauri/src/dashboard/slack_oauth.rs`
- 허락을 기다리는 동안만 `127.0.0.1`과 `::1`의 47823(사용 중이면 47824, 47825) 포트를 연다. 5분 뒤나 취소하면 닫는다.
- `state`가 다른 요청은 거절하고 계속 기다린다.
- 토큰은 기존처럼 키체인(`prism.slack`)에만 저장한다. 만료형이면 갱신용 값을 `refresh` 항목에 두고, 만료 5분 전부터 API를 부르기 전에 갱신한다. 문서가 localhost에서도 만료형이 강제되는지 밝히지 않아 두 경우를 모두 처리한다.
- Client ID 우선순위: 화면에서 넣은 값 → 환경 변수 `PRISM_SLACK_CLIENT_ID` → `src-tauri/slack-app.json`
- 권한: `channels:read` `channels:history` `groups:read` `groups:history` `users:read` (`auth.test`는 권한 불필요)

### 남은 확인 (진짜 슬랙 앱이 생긴 뒤)

지금까지는 가짜 서버 시험(`cargo test slack`)만 했다.

1. 매니페스트가 그대로 받아들여지는지, 연결이 끝까지 되는지.
2. 토큰이 만료형으로 오는지. 사용자 토큰 **갱신** 응답의 모양은 문서가 분명하지 않아, 맨 위와 `authed_user` 안 둘 다 읽게 해 두었다. 12시간 뒤에도 읽히는지 확인한다.
3. 관리자 승인이 필요한 워크스페이스에서 리다이렉트로 무엇이 돌아오는지 (문서에 없음. 지금은 안 돌아와도 되도록 화면에 안내를 둔다).
4. `http://localhost`를 등록한 채 Public Distribution을 켤 수 있는지. 막히면 https 정적 페이지 하나가 `code`와 `state`를 localhost로 넘기는 방법이 있다(secret 없이 PKCE 유지). 이 경우 슬랙이 데스크톱 리다이렉트로 보지 않을 수 있어 먼저 시험이 필요하다.
