# Prism: 디자인 브리프

> 프로젝트마다 AI 팀을 고용해 두고, **출근 버튼 하나**로 일을 시키는 데스크톱 앱.
> 사용자는 총괄 에이전트와만 대화한다. 총괄은 일을 작업 카드로 쪼개 아래 층에 하청을 주고, 결과는 요약만 위로 올라온다.

- 플랫폼: macOS, Windows 데스크톱 앱 (Tauri 2 + React 19 + TypeScript)
- 창 크기: 기본 1280×800, 최소 900×600
- 언어: 한국어 UI (영문 병기 가능)

---

## 1. 제품 콘셉트

### 1.1 한 줄 정의
git worktree 단위로 작업 공간을 나누고, 각 공간 안에 **총괄 1명 → 팀장 N명 → 작업자 N명**으로 이루어진 AI 개발팀을 운영하는 관제탑 앱.

### 1.2 원본 Orca와의 차이
| | 원본 Orca | Prism |
|---|---|---|
| 구조 | worktree마다 에이전트가 독립적으로 나란히 실행 | worktree마다 계층형 팀 (총괄, 팀장, 작업자) |
| 사람의 역할 | 모든 터미널을 직접 오가며 관리 | 총괄과만 대화하고 나머지는 상태만 확인 |
| 지시 방식 | 각 에이전트에 직접 입력 | 자연어로 지시하면 작업 카드로 자동 하청 |
| 시각화 | 터미널 탭, 목록 | 유리 레이어 스택으로 조직과 작업 흐름을 표현 |

### 1.3 핵심 원칙
1. **사람에게는 자연어, 내부는 작업 카드.** 사용자는 편하게 말하고, 에이전트끼리는 구조화된 카드로 주고받는다.
2. **기억은 앱이, 에이전트는 교체 가능.** 모든 작업은 앱의 작업 로그에 남는다. 에이전트가 재시작해도 로그를 읽고 이어서 일한다(카프카 방식).
3. **끝없는 지시.** 총괄은 지시를 받으면 즉시 "접수"하고 큐에 넣는다. 사용자는 기다리지 않고 계속 다음 지시를 할 수 있다.
4. **알림은 위로 올라온다.** 막힌 일은 작업자 → 팀장 → 총괄 → 사용자 순서로 올라온다. 사람이 판단해야 하는 것만 사용자에게 도착한다.

## 2. 사용자 흐름

```
프로젝트 열기 → [▶ 팀 출근] → 레이어 스택 뷰
      → 총괄 채팅에 "로그인 만들어" → 총괄: "접수, 3개로 분해"
      → 작업 카드가 층을 따라 내려감 → 각 층 노드 상태 변화
      → (계속) "결제도 해줘" → 접수 → ...
      → 작업자 막힘 🔴 → 신호가 위로 전파 → 사용자 알림 → 응답
      → 완료 보고(요약)가 위로 올라감 → 작업 보드 '완료'로 이동
```

## 3. 화면 구성

### 3.1 프로젝트 홈 / 팀 출근
- 최근 프로젝트(레포) 목록을 유리 카드로 보여준다.
- 프로젝트를 선택하면 **팀 구성 미리보기**가 나온다: 역할별 인원과 모델(예: 총괄 opus, 팀장 sonnet ×3, 작업자 haiku ×6).
- 프리셋 토글: 💰 절약 / 🎯 균형 / ⚡ 파워.
- 큰 **[▶ 팀 출근]** 버튼. 누르면 노드가 아래층부터 차례로 켜지는 애니메이션이 재생되고 메인 화면으로 넘어간다.

### 3.2 메인 (관제탑): 3단 레이아웃
```
┌──────────────┬────────────────────────────────┬──────────────────┐
│ 💬 총괄 채팅  │      🧊 레이어 스택 뷰            │ 📋 작업 보드      │
│              │                                │                  │
│ 나: 로그인    │      ╱‾‾‾‾ 🗼 총괄 ‾‾‾‾╲          │ 대기     ▢▢       │
│   만들어     │      ╲________________╱         │ 배정     ▢        │
│ 총괄: 접수,  │            ● ↓                  │ 진행중   ▢▢▢      │
│  3개로 분해  │      ╱‾‾ 🧑‍💼 팀장 A · B ‾‾╲       │ 검토     ▢        │
│ 나: 결제도   │      ╲________________╱         │ 완료     ▢▢▢▢     │
│ 총괄: 접수   │      ╱‾‾ 🤖 A1 A2 B1 B2 ‾‾╲       │──────────────────│
│              │      ╲________________╱         │ 📜 이벤트 로그     │
│ [입력창    ] │                                │ 09:31 T-12 배정   │
└──────────────┴────────────────────────────────┴──────────────────┘
 상단 바: 프로젝트명 · worktree 선택 · 프리셋 · 💰 비용 미터 · 알림
```
- **왼쪽 (약 320px): 총괄 채팅.** 끝없이 이어지는 대화. 총괄의 답변 중 작업 카드 요약은 인라인 칩(`T-12 로그인 API`)으로 표시하고, 칩을 클릭하면 해당 카드로 이동한다.
- **가운데 (가변): 레이어 스택 뷰.** 핵심 시각화이며 4장에서 자세히 다룬다.
- **오른쪽 (약 340px): 작업 보드 + 이벤트 로그.** 칸반 5열(대기, 배정, 진행중, 검토, 완료) 아래에 시간순으로 흐르는 이벤트 로그가 있다.
- 좌우 패널은 접을 수 있다. 접으면 스택 뷰가 넓어진다.

### 3.3 레이어 집중 뷰
- 스택에서 한 층을 클릭하면 그 유리판이 회전하며 정면으로 와서 2D 화면으로 펼쳐진다.
- 해당 층의 에이전트 노드가 **카드 그리드**로 배치되고, 각 카드에 상태, 현재 작업, 모델, 미니 터미널 미리보기가 들어간다.
- 상단 브레드크럼: `스택 › 팀장 층`. 뒤로 가면 다시 기울어지며 스택으로 돌아간다.

### 3.4 에이전트 상세
- 큰 터미널(실제 PTY 출력, xterm.js)을 띄우고 사용자가 직접 끼어들어 입력할 수 있다.
- 오른쪽 정보 패널:
  - 맡은 작업 카드
  - 모델 드롭다운(즉석 승격/강등)
  - 상위 노드 링크
  - 변경 파일 목록과 diff 보기
  - 토큰 사용량
- 액션: 일시정지, 재시작(세션 resume), 종료, 메시지 보내기.

### 3.5 팀 설정 (프리셋 편집기)
- 역할별 행(총괄, 팀장, 작업자)마다 에이전트 종류(Claude, Codex, Gemini 등), 모델, 최대 인원을 설정한다.
- 동시 실행 상한과 일일 예산을 설정한다.
- 레포의 `prism.yaml`과 양방향으로 동기화된다. 코드 미리보기 토글을 제공한다.

### 3.6 알림 / 에스컬레이션
- 막힘이 발생하면 스택 뷰에서 빨간 신호가 해당 노드부터 위층으로 타고 올라간다.
- 그다음 상단 알림 토스트와 OS 알림이 뜬다.
- 토스트 내용: 어느 에이전트가, 무엇 때문에 막혔는지, 바로 답하는 입력창.

## 4. 시그니처 요소: 레이어 스택 뷰

레퍼런스 이미지(첨부: 반투명 유리 UI 판이 아이소메트릭으로 층층이 쌓인 일러스트)를 그대로 정보 구조로 바꾼다.

| 시각 요소 | 의미 |
|---|---|
| 유리판 1장 | 계층 1단계 (위에서부터 총괄 → 팀장 → 작업자) |
| 판 위의 노드(작은 유리 타일) | 개별 에이전트. 아이콘, 이름, 상태 점 |
| 판 주변에 떠 있는 작은 아이콘 | 그 층에 대기 중인 작업 카드 |
| 층 사이를 내려가는 빛나는 점 | 하청 중인 작업 카드 |
| 위로 올라가는 점 | 보고 |
| 빨간 펄스가 위로 전파 | 막힘 에스컬레이션 |

### 인터랙션
- **기본:** 아이소메트릭 각도(대략 `rotateX(55deg) rotateZ(-45deg)`), 층 간격은 촘촘하게.
- **호버:** 층 간격이 부드럽게 벌어진다(exploded view). 호버한 층은 살짝 떠오르고 밝아진다.
- **노드 호버:** 툴팁 카드에 현재 작업, 모델, 경과 시간을 보여준다.
- **층 클릭:** 판이 정면으로 회전하며 집중 뷰로 전환된다(공유 레이아웃 애니메이션).
- **노드 클릭:** 에이전트 상세로 이동한다.
- 층이 하나뿐인 초기 상태(총괄 → 작업자 2단계)도 자연스럽게 보여야 한다.

## 5. 비주얼 언어

### 5.1 무드
따뜻하고 차분한 **크림·베이지 톤**에 **서리 낀 유리(frosted glass)** 질감. 종이처럼 부드러운 그림자, 은은한 빛 번짐. 개발 도구지만 차갑지 않고 공예품 같은 느낌.

### 5.2 컬러 토큰
| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `bg-base` | `#EFE6D8` → `#F7F2EA` 그라데이션 | `#1C1814` → `#2A231C` | 앱 배경 |
| `glass-fill` | `rgba(255,255,255,0.45)` | `rgba(255,248,238,0.06)` | 유리 패널 |
| `glass-border` | `rgba(255,255,255,0.7)` | `rgba(255,240,220,0.14)` | 유리 테두리 하이라이트 |
| `glass-shadow` | `0 20px 40px rgba(120,90,50,0.15)` | `0 20px 40px rgba(0,0,0,0.45)` | 떠 있는 그림자 |
| `text-primary` | `#2B2520` | `#F3ECE2` | 본문 |
| `text-secondary` | `#7A6E62` | `#A89C8E` | 보조 |
| `accent-amber` | `#E8A15A` | `#F0B070` | 주요 액션, 진행 중 하이라이트 |
| `accent-navy` | `#2F3E66` | `#8FA3D6` | 링크, 선택 |
| `accent-sky` | `#BFD4E6` | `#5F7FA0` | 보조 강조 |

**상태색** (채도 낮게, 웜톤에 어울리게)
| 상태 | 색 | 표현 |
|---|---|---|
| working (진행) | `#7FB08A` 세이지 그린 | 천천히 숨쉬는 펄스 |
| waiting (대기) | `#E2B866` 머스터드 | 정적 |
| blocked (막힘) | `#D9725F` 테라코타 | 빠른 펄스와 위로 전파 |
| done (완료) | `#9A9188` 웜그레이 + ✓ | 페이드 |

### 5.3 유리 패널 스펙
- `backdrop-filter: blur(20px) saturate(140%)`
- 1px 테두리 `glass-border`와 위쪽 안쪽 하이라이트(`inset 0 1px 0 rgba(255,255,255,0.6)`)
- 모서리: 패널 16px, 카드 12px, 칩 999px
- 창 자체: macOS는 vibrancy, Windows는 Mica/Acrylic(Tauri `windowEffects`)

### 5.4 타이포그래피
- UI: **Pretendard** (한글), 13/14/16/20/28px
- 코드, 터미널, 카드 ID: **JetBrains Mono** 12/13px
- 굵기: 400 본문, 500 라벨, 600 제목

### 5.5 아이콘
- lucide 계열 라인 아이콘, 1.5px stroke
- 역할 아이콘: 🗼 총괄(타워), 🧑‍💼 팀장(브리프케이스), 🤖 작업자(봇). 최종 디자인에서는 이모지를 라인 아이콘으로 교체한다.

## 6. 모션

모든 전환은 **스프링 물리 기반**으로 부드럽게 한다. 갑작스러운 등장이나 사라짐은 없다.

| 모션 | 스펙 |
|---|---|
| 기본 스프링 | stiffness 260, damping 28 (약 350ms 체감) |
| 층 펼치기/접기 | 스프링, 층마다 40ms stagger |
| 스택 → 집중 뷰 | 공유 레이아웃 전환 약 500ms, 회전과 확대 동시 진행 |
| 작업 카드 하강 | 600~800ms ease-in-out, 빛 꼬리(trail) |
| 팀 출근 | 아래층부터 노드가 하나씩 페이드인과 스케일업(stagger 60ms) |
| working 펄스 | 2s 주기 opacity 0.6↔1 |
| blocked 전파 | 노드 → 상위 노드로 300ms 간격 빨간 링 |
| 패널 등장 | opacity와 translateY 8px, 200ms |

- 구현: Motion(Framer Motion), CSS 3D transform
- 성능: 애니메이션은 `transform`과 `opacity`만 사용한다. 60fps를 유지해야 한다.
- 접근성: `prefers-reduced-motion`이 켜져 있으면 회전과 하강을 끄고 페이드만 남긴다.

## 7. 데이터: 작업 카드

UI의 작업 보드 카드, 스택의 떠 있는 아이콘, 채팅 칩은 모두 이 데이터 하나에서 그려진다.

```json
{
  "id": "T-12",
  "parent": "T-10",
  "assignee": "worker:A1",
  "model": "haiku",
  "goal": "카카오 소셜로그인 구현",
  "files": ["src/auth/"],
  "done_when": ["pnpm test auth 통과"],
  "depends_on": ["T-11"],
  "status": "working",
  "summary": null,
  "cost_usd": 0.04
}
```

카드 컴포넌트에 표시할 것:
- ID 칩과 goal(1~2줄)
- 담당 노드 아바타와 모델 배지
- 상태 점과 의존성 표시(🔗 T-11)
- 완료 시 summary 3줄과 비용

## 8. 팀 프리셋 (prism.yaml)

```yaml
team:
  lead:     { agent: claude, model: opus }
  managers: { agent: claude, model: sonnet, max: 3 }
  workers:  { agent: claude, model: haiku,  max: 6 }
limits:
  concurrent: 8
  daily_budget_usd: 20
```
- 역할별로 모델을 나눠 비용을 절감한다. 판단은 비싼 모델이, 실행은 싼 모델이 맡는다.
- 노드마다 모델을 즉석에서 변경할 수 있고, 작업 단위로 덮어쓸 수도 있다("이건 opus로").

## 10. 제약과 주의사항

- **터미널 영역에는 blur를 쓰지 않는다.** 계속 갱신되는 영역에 blur를 걸면 성능이 떨어진다. 불투명에 가까운 어두운 패널 위에 둔다.
- 유리 레이어는 한 화면에 3~4겹 이하로 쌓는다(GPU 부담).
- 라이트/다크 모드를 모두 지원하고, 다크에서는 유리판이 은은하게 빛나는 느낌으로 처리한다.
- macOS 창 상단 신호등 버튼 영역(왼쪽 약 80px)과 Windows 창 제어 버튼 영역(오른쪽)을 비워 둔다.
- 대비는 본문 텍스트 기준 WCAG AA를 유지한다. 유리 위 텍스트는 대비를 꼭 확인한다.

## 11. 디자인 요청 범위

우선순위 순서:
1. **메인 관제탑 화면** (3단 레이아웃과 레이어 스택 뷰), 라이트·다크
2. **레이어 집중 뷰**와 스택 → 집중 전환의 키프레임
3. **에이전트 상세** (터미널과 정보 패널)
4. **프로젝트 홈 / 팀 출근**
5. **팀 설정**
6. 컴포넌트 시트 (9장)

> 참고 이미지: 따뜻한 베이지 배경 위에 반투명 유리 UI 판들이 아이소메트릭으로 층층이 떠 있고, 주변에 작은 아이콘 조각들이 흩어진 일러스트. 이 문서와 함께 첨부할 것.
